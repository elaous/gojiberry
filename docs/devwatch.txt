package devwatch // import "github.com/elaous/gojiberry/devwatch"

Package devwatch is the process-supervision half of gox's dev loop: watch a
source tree, and on a relevant change, rebuild and restart a managed server
subprocess. Pair it with the sibling devreload package for the browser-side half
(reloading a tab once the restarted process is listening again).

This began as examples/canvas-app's own cmd/devwatch, hardcoded to that app's
`make generate`/`make wasm`/cmd/devserver specifics; this package is that
same watch/debounce/rebuild/restart loop generalized behind a Config so any
gox project's own thin cmd/devwatch (or cmd/goxdev, for a project with no Go
code of its own to add) can reuse it instead of re-deriving fsnotify wiring
and subprocess lifecycle management from scratch. It is not real hot module
replacement -- a compiled binary (or .wasm blob) is one opaque unit, not a set
of hot-swappable modules -- just a fast watch/rebuild/ restart/reload loop,
an acceptable tradeoff for any gox app whose server holds no unrecoverable
in-memory state a full restart would lose (canvas-app's own state lives in
Postgres, for instance).

FUNCTIONS

func DefaultIgnore(path string) bool
    DefaultIgnore reports whether path should never trigger a rebuild regardless
    of project: VCS metadata (.git) and goxc's own generated *.gox.go files
    (edit the .gox source instead -- watching the file goxc itself just wrote
    would create a feedback loop). A project's own build-output directories
    (a WASM static/ dir, a temp binary path, ...) are not covered here since
    there's no universal convention for them; combine with Config.Ignore for
    those.

func Run(cfg Config) error
    Run performs cfg.Rebuild once, starts the managed process, then watches
    cfg.Root: on a relevant change (debounced 200ms so a burst of saves triggers
    one rebuild, not several), it reruns cfg.Rebuild and, if that succeeds,
    restarts the managed process. It blocks until SIGINT/SIGTERM, cleaning up
    the managed process before returning nil. A failed initial build is returned
    as an error rather than started at all, since there would be nothing working
    yet to fall back to.


TYPES

type Config struct {
	// Root is the directory tree to watch, recursively.
	Root string

	// Ignore reports whether a changed path should never trigger a
	// rebuild. Combine with DefaultIgnore to keep its universal skips
	// (VCS metadata, generated *.gox.go files) alongside a project's
	// own build-output paths, e.g.:
	//
	//	Ignore: func(p string) bool {
	//		return devwatch.DefaultIgnore(p) || strings.Contains(p, "/static/")
	//	}
	//
	// A nil Ignore is equivalent to DefaultIgnore alone.
	Ignore func(path string) bool

	// Rebuild runs the project's build steps (regenerating .go from
	// .gox, compiling a WASM client, building the server binary this
	// Config's Command runs, ...), streaming their own output as they
	// go. It reports whether the build succeeded; false leaves whatever
	// server is currently running alone rather than restarting it into
	// a known-broken state.
	Rebuild func() bool

	// Command and Args launch the built server binary. Run executes it
	// directly (not through a shell), so a signal sent to stop it
	// reaches the real server process, not an intermediary.
	Command string
	Args    []string

	// Env, if non-nil, replaces the managed process's environment
	// entirely; leave nil to inherit Run's own environment unchanged.
	Env []string
}
    Config configures Run. Root, Rebuild, and Command are required; the rest
    have workable zero values.
